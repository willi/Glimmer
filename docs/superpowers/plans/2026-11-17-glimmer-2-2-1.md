### Task 3: Tables fit their columns to the width

**Files:**
- Modify: `Sources/Glimmer/Engine/Embeds/GlimmerTableView.swift` (`layout(forWidth:)` ~:209-237, `naturalRowWidths`)
- Modify: `Sources/Glimmer/Engine/Theme/GlimmerTheme.swift` (new `minTableColumnWidth: CGFloat`, default 72, doc-commented; added to `.default` and `scaled(for:)`)
- Test: `Tests/GlimmerTests/Engine/GlimmerTableViewTests.swift`

**Interfaces:**
- Produces: `GlimmerTheme.minTableColumnWidth` (public var). Behaviour: when the columns' natural widths (each capped at `maxTableColumnWidth`) don't fit the available width, columns shrink toward `minTableColumnWidth` — wider columns give up width first (shrink proportionally to how far each is above the minimum) — and cell text wraps, so rows grow taller. Only when every column is at the minimum and they still don't fit does the table scroll sideways as in 2.2.0. A table that already fits is laid out exactly as in 2.2.0.

### Task 4: `GlimmerStaticText`, block layout in SwiftUI

**Files:**
- Create: `Sources/Glimmer/Engine/Static/GlimmerStaticText.swift` (public SwiftUI view)
- Create: `Sources/Glimmer/Engine/Static/GlimmerStaticDocument.swift` (internal model: the blocks to render, built from markdown)
- Create: further one-type-per-file internal views as needed (`GlimmerStaticBlockView`, `GlimmerStaticListView`, …)
- Modify: `README.md` (section "Static text in SwiftUI", next to "Plain attributed text"), `GlimmerReadmeExampleTests.swift`
- Test: `Tests/GlimmerTests/Engine/GlimmerStaticTextTests.swift`

**Interfaces:**
- Consumes: `GlimmerParser.parse`, the extensions' `prepared(_:isStreaming: false)`, and the inline conversion behind `GlimmerView.attributedString` (reuse it for each block's inline runs; do not duplicate it).
- Produces:
  - `public struct GlimmerStaticText: View` — `public init(_ markdown: String, configuration: GlimmerConfiguration = .default, onLinkTap: ((URL) -> Void)? = nil)`. Reads `@Environment(\.dynamicTypeSize)` for fonts. Renders, top to bottom in a `VStack(alignment: .leading)` with the theme's spacing between blocks: paragraphs and headings as `Text`; bullet and ordered lists as rows of marker + content with a hanging indent of `theme.listIndent` (nested lists indent again; task items show ☑︎/☐ as markers); block quotes with a leading bar in `theme.quoteBarColor` and `secondaryTextColor` text; code blocks as monospaced `Text` on `theme.codeBlockBackground`; tables as one `Text` row per line, cells separated by a tab; thematic breaks as a 1 pt rule; images left out (as in `attributedString`). Links are tappable: an `openURL` action calls `onLinkTap`, or falls back to the system when it is nil.
  - `.lineLimit(n)` applies per `Text` (environment), so a single-paragraph document truncates like `Text`.
  - `GlimmerStaticDocument` (internal): `init(markdown:configuration:dynamicTypeSize:)` and a `blocks` array of an internal enum the views switch on; built once per input and cached in the view's state keyed by the inputs.
