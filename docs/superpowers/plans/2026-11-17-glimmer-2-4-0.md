# Glimmer 2.4.0: link policy and per-role spacing — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a host decide which links become links, and let it set line height per text role and loose-list spacing, so SuperMe can drop its markdown link-rewriter and match its previous chat typography exactly.

**Architecture:** A `GlimmerLinkPolicy` protocol modelled on `GlimmerImagePolicy`, checked at the one place every link is composed (`case .link` in `GlimmerComposer+Inlines.swift` — inline links, `<autolinks>` and GFM bare URLs all arrive as `.link` nodes). New optional `GlimmerTheme` fields for heading and code line height and loose-list spacing; `nil` keeps 2.3.0 behaviour. A small fix: linked chip text in plain attributed output takes the link colour.

**Tech Stack:** Swift 6, UIKit, TextKit 2, SwiftUI, XCTest. iOS 26 floor; builds with Xcode 26.5 and 27.

**Why (SuperMe's whole-branch review, Nov 17):** SuperMe enforces a link-scheme allowlist by rewriting markdown text before parsing. A `]` inside an autolink or raw HTML in a link's text makes that rewriter and cmark disagree, so `someapp://` links still reach UIKit's long-press "Open Link" menu. And a chat-only `lineHeightMultiple` that restores body pitch also stretches headings (+2–3 pt) and code (+1.3 pt per line), because one multiple applies to all text. Willi chose fixing both in Glimmer.

### Task 1: Link policy

**Files:**
- Create: `Sources/Glimmer/Engine/GlimmerLinkPolicy.swift` (protocol + `GlimmerLinkDecision`), `Sources/Glimmer/Engine/GlimmerLinkCandidate.swift`, `Sources/Glimmer/Engine/Embeds/GlimmerLinkPolicyKey.swift` (Hashable wrapper, copy `GlimmerImagePolicyKey`)
- Modify: `GlimmerConfiguration.swift` (new `linkPolicy`), `Compose/GlimmerComposer.swift` + `GlimmerComposer+Inlines.swift` (`case .link`), `Stream/GlimmerDocumentCache.swift` key, `GlimmerView.swift` (`makeDocument`, cache key), `Compose/GlimmerPlainText.swift` composer factory, `Interact/GlimmerMarkdownSerializer.swift` if copy needs it, README ("Link policy" section after "Image policy")
- Test: `Tests/GlimmerTests/Engine/GlimmerLinkPolicyTests.swift`

**Interfaces:**
- `public enum GlimmerLinkDecision: Sendable, Hashable { case link; case text }` — `.text` composes the link's children as ordinary text, styled like the text around them (no link colour, underline or `.link` attribute).
- `public struct GlimmerLinkCandidate: Sendable, Hashable { public let destination: String; public let url: URL?; public let title: String? }` (`url` is `URL(string: destination)`).
- `public protocol GlimmerLinkPolicy: Sendable, Hashable { func decision(for link: GlimmerLinkCandidate) -> GlimmerLinkDecision }` — doc like `GlimmerImagePolicy`: asked from any thread, more than once; equal policies decide equally.
- `GlimmerConfiguration.linkPolicy: (any GlimmerLinkPolicy)?` (default `nil` = every link is a link, as 2.3.0); init parameter added last with default `nil`.
- Covered: inline links, autolinks and GFM bare URLs (all `.link` nodes). Not covered, documented: extension tokens (the host routes `onTokenTap`), data detectors.
- The document cache key and `GlimmerStaticText`'s cache key include the policy (as the image policy is included).
- Copy: `markdownSource()` writes a refused link as its text only (the URL is never handed out), like a refused image; `plainText()` unchanged.
